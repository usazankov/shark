# Процесс разработки

- Версия: 1.0
- Связанные документы: [Обзор архитектуры](overview.md) · [Требования](../requirements.md)

## 1. Ветки и коммиты

- **Trunk-based:** работаем маленькими коммитами в `main`; `main` всегда зелёная
  (build + тесты проходят). Если коммит ломает сборку — чинится немедленно,
  прежде чем что-либо новое.
- Формат коммитов — Conventional Commits, в скопе — слой:

  ```
  feat(core): FR-7 рост змейки при поедании
  fix(render): FR-9 рекорд не обновлялся на Game Over
  test(core): FR-8 покрытие смерти о стену и о себя
  docs: уточнение FR-11 после игротестов
  chore: настройка eslint
  ```

- Ссылка на ID требования (`FR-N` / `NFR-N`) в коммите обязательна, если коммит
  меняет поведение игры — так каждое изменение прослеживается до требования.

## 2. Тестирование

- **Юнит (Vitest):** вся логика `core/` — движение, коллизии, еда, счёт,
  ускорение, буфер направлений, смерть о стену/себя. Цель ≥ 90% строк `core/`.
- Имена тестов — по требованию: `describe('FR-8: смерть')` →
  `it('змея умирает при столкновении со стеной')`.
- Тесты детерминированы: случайность через сид в `GameState`, никаких реальных
  таймеров — интервал тика проверяется значением в состоянии.
- **Смоук:** перед «готово» — раунд в браузере по чек-листу скилла
  `snake-verify` (запуск игры, повороты, еда, смерть, рестарт, пауза, рекорд).

## 3. Качество

- TypeScript strict; `any` запрещён, кроме точечных `eslint-disable` с причиной.
- ESLint + Prettier; проверка запускается до коммита.
- Перед «готово» всегда зелёные: `npm run build`, `npm test`, `npm run lint`.

## 4. Цикл задачи

1. Прочитать [requirements.md](../requirements.md) — *что* делаем (найти FR/NFR;
   если требования нет — сначала дописать его).
2. Прочитать [modules.md](modules.md) — *куда* ложится изменение.
3. Написать тест на желаемое поведение — красный.
4. Минимальная реализация — зелёный.
5. Рефакторинг в рамках правил модулей.
6. Коммит `feat(слой): FR-N описание`.

## 5. Скиллы проекта

| Скилл            | Когда использовать                                       |
| ---------------- | -------------------------------------------------------- |
| `snake-implement` | любая задача по коду игры: фича, баг, правка логики     |
| `snake-verify`   | проверка после изменений и перед коммитом; «прогони тесты» |
| `snake-review`   | ревью дифа на соответствие требованиям и архитектуре    |

Живут в `.agents/skills/`, доступны как `/snake-implement` и т.д.
