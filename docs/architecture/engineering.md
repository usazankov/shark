# Процесс разработки

- Версия: 1.1 (стек C + Raylib)
- Связанные документы: [Обзор архитектуры](overview.md) · [Требования](../requirements.md)

## 1. Окружение

- Компилятор: GCC (MinGW-w64) из MSYS2, плюс пакеты `cmake`, `ninja`,
  `mingw-w64-x86_64-raylib`.
- Сборка и тесты идут из «MSYS2 MinGW64»-оболочки (или любого терминала с
  `mingw64/bin` в PATH).
- Первичная настройка машины описана в README проекта.

## 2. Ветки и коммиты

- **Trunk-based:** работаем маленькими коммитами в `main`; `main` всегда зелёная
  (сборка + тесты проходят). Если коммит ломает сборку — чинится немедленно,
  прежде чем что-либо новое.
- Формат коммитов — Conventional Commits, в скопе — слой:

  ```
  feat(core): FR-7 рост змейки при поедании
  fix(render): FR-9 рекорд не обновлялся на Game Over
  test(core): FR-8 покрытие смерти о стену и о себя
  docs: уточнение FR-11 после игротестов
  chore: пресет сборки под MSVC
  ```

- Ссылка на ID требования (`FR-N` / `NFR-N`) в коммите обязательна, если коммит
  меняет поведение игры — так каждое изменение прослеживается до требования.

## 3. Сборка и тесты

```bash
cmake --preset default        # конфигурация (Ninja, out-of-source в build/)
cmake --build build           # сборка; НОЛЬ предупреждений (NFR-7)
ctest --test-dir build        # юнит-тесты Unity через CTest
./build/snake.exe             # запуск игры
```

- **Юнит (Unity, `tests/core_tests.c`):** вся логика `core/` — движение,
  коллизии, еда, счёт, ускорение, буфер направлений, смерть о стену/себя.
  Цель ≥ 90% строк `core/`.
- Имена тестов — по требованию: `RUN_TEST(test_fr8_death_by_wall)` и т.п.
- Тесты детерминированы: случайность через сид в `GameState`, никаких реальных
  таймеров — интервал тика проверяется значением в состоянии.
- **Смоук:** перед «готово» — раунд по чек-листу скилла `snake-verify`
  (запуск игры, повороты, еда, смерть, рестарт, пауза, рекорд).
- Раз перед релизом v1 — прогон под ASan/UBSan (или Valgrind): C без RAII,
  утечки и выходы за границы ловим инструментами, не глазами (риск из
  requirements §7).

## 4. Качество

- C11 без расширений; флаги `-Wall -Wextra -Wpedantic -Werror -std=c11` —
  базовое определение «собралось чисто».
- Форматирование — clang-format (файл `.clang-format` в корне), запуск перед
  коммитом.
- Перед «готово» всегда зелёные: сборка, `ctest`, смоук.

## 5. Цикл задачи

1. Прочитать [requirements.md](../requirements.md) — *что* делаем (найти FR/NFR;
   если требования нет — сначала дописать его).
2. Прочитать [modules.md](modules.md) — *куда* ложится изменение.
3. Написать тест на желаемое поведение — красный.
4. Минимальная реализация — зелёный.
5. Рефакторинг в рамках правил модулей.
6. Коммит `feat(слой): FR-N описание`.

## 6. Скиллы проекта

| Скилл            | Когда использовать                                       |
| ---------------- | -------------------------------------------------------- |
| `snake-implement` | любая задача по коду игры: фича, баг, правка логики     |
| `snake-verify`   | проверка после изменений и перед коммитом; «прогони тесты» |
| `snake-review`   | ревью дифа на соответствие требованиям и архитектуре    |

Живут в `.agents/skills/`, доступны как `/snake-implement` и т.д.
