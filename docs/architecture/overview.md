# Архитектура: обзор

- Версия: 1.0
- Связанные документы: [Требования](../requirements.md) · [Модули](modules.md) · [Процесс](engineering.md)

## 1. Ключевой принцип: чистое ядро

Вся игровая логика (правила, движение, столкновения, еда, счёт, скорость) —
**чистое ядро** без DOM, canvas, таймеров и глобального `Math.random()`. Ядро:

1. получает состояние игры и вход (буфер направлений),
2. возвращает новое состояние и список событий (`ate`, `died`, `turned`),
3. источник случайности — ГПСЧ с сидом, живущим в состоянии.

**Почему:** детерминизм и юнит-тесты без браузера (NFR-3), воспроизводимость багов
по сиду, возможность позже подключить бота или авто-тесты геймплея.

## 2. Слои

```
┌─────────────────────────────────────────────┐
│ app (main.ts)   точка входа, game loop,     │
│                 связывание слоёв            │
├─────────────────────────────────────────────┤
│ input           клавиатура/свайпы →         │
│                 буфер направлений           │
├─────────────────────────────────────────────┤
│ core            ЧИСТАЯ ЛОГИКА: поле,        │
│                 змейка, еда, правила, счёт  │
├─────────────────────────────────────────────┤
│ render          отрисовка состояния на      │
│                 canvas (только чтение)      │
├─────────────────────────────────────────────┤
│ storage         localStorage: рекорды,      │
│                 настройки (обёртка)         │
└─────────────────────────────────────────────┘
```

Правила зависимостей (стрелки только вниз):

- `core` не знает ни о каком другом слое — его можно собрать и тестировать в Node без браузера.
- `input` и `storage` используют типы `core`, но не наоборот.
- `render` читает состояние и никогда не мутирует его.
- `app/main.ts` — единственное место, связывающее всё вместе.

## 3. Игровой цикл

- **Fixed timestep:** логика тикает с фиксированным интервалом (клетка за тик),
  рендер — на `requestAnimationFrame`.
- Накопитель времени (accumulator): на медленном железе логика «догоняет»,
  на быстром — не ускоряется. Скорость игры меняется только интервалом тика
  (FR-11), а не шагом движения.
- Ввод собирается между тиками в буфер (FR-5) и применяется на тике.

## 4. Состояние

Один объект `GameState`: поле, змейка, еда, направление, счёт, статус
(`menu | running | paused | gameover`), интервал тика, сид ГПСЧ. Мутируется
только внутри `core` — единственная точка изменения это функция `tick`
(контракт в [modules.md](modules.md)).

## 5. Расширяемость (не-цели v1, но заложить)

| Расширение       | Как ложится на архитектуру                              |
| ---------------- | ------------------------------------------------------- |
| Бонусная еда     | новая сущность в `core` + отрисовка; контракт `tick` не меняется |
| Препятствия/уровни | массив `walls[]` в состоянии, те же правила коллизий  |
| Звук             | подписка на события `GameEvent[]`, возвращает `tick`   |
| Таблица рекордов онлайн | замена реализации `storage/scores.ts`, интерфейс тот же |

## 6. Технические решения (ADR)

- **ADR-001 — TypeScript strict.** Логика координат и направлений — главный
  источник багов в змейке; типы ловят их дёшево.
- **ADR-002 — Canvas 2D вместо DOM/SVG/WebGL.** ~400 прямоугольников за кадр —
  ноль проблем для Canvas; WebGL и движки не оправдают сложность.
- **ADR-003 — Vite.** Dev-сервер без конфига, быстрая сборка, TS из коробки.
- **ADR-004 — Vitest.** Тесты `core` выполняются в Node без браузера (NFR-3).
- **ADR-005 — localStorage за обёрткой.** Приватный режим/блокировки хранилища
  не должны ронять игру; обёртка тестируется и имеет in-memory fallback.
