# Требования к игре «Змейка»

- Версия: 1.0 (черновик к согласованию)
- Дата: 2026-10-03
- Статус: v1 — классическая змейка, без мультиплеера

## 1. Обзор

Классическая «Змейка»: игрок управляет змейкой на клеточном поле, собирает еду,
растёт и не должен врезаться в стены и в собственное тело. Цель — набрать
максимум очков. Одна партия длится 1–5 минут.

## 2. Цели и не-цели

**Цели v1:**

- Играбельная классическая змейка в браузере (desktop и мобильные).
- Чистая, тестируемая архитектура: игровая логика отделена от отрисовки и ввода.
- Рекорды сохраняются между сессиями.

**Не-цели v1** (архитектура должна допускать добавление позже):

- Мультиплеер, онлайн-таблица рекордов.
- Уровни, препятствия, бонусы кроме базовой еды.
- Звук и музыка.
- Оффлайн-установка (PWA).

## 3. Стек и платформа

| Что      | Решение                              | Почему                                              |
| -------- | ------------------------------------ | --------------------------------------------------- |
| Язык     | TypeScript (strict)                  | Ловит ошибки в логике координат, читаемые контракты |
| Графика  | HTML5 Canvas 2D                      | Змейка тривиальна для растеризации, 60 FPS без усилий, ноль зависимостей |
| Сборка   | Vite                                 | Мгновенный dev-сервер, минимальный конфиг, TS из коробки |
| Тесты    | Vitest                               | Юнит-тесты логики без браузера, совместим с Vite    |
| Движок   | нет (нативный Canvas)                | Никакой фреймворк не оправдает свой вес для змейки  |

Поддерживаемые браузеры: две последние мажорные версии Chrome, Edge, Firefox,
Safari; desktop и мобильные.

## 4. Функциональные требования

У каждого требования есть ID — на него ссылаются коммиты, тесты и ревью.

### Игровое поле

- **FR-1.** Поле — сетка клеток N×M. Базовый размер 20×20, задаётся в конфиге.
- **FR-2.** Змейка стартует длиной 3 в центре поля, начальное направление — вправо.

### Управление

- **FR-3.** Управление: стрелки и WASD; на тач-устройствах — свайпы.
- **FR-4.** Разворот на 180° игнорируется — нельзя умереть от нажатия «назад».
- **FR-5.** Ввод буферизуется (очередь до 2 направлений), чтобы быстрые
  последовательные повороты не терялись.

### Еда и рост

- **FR-6.** На поле всегда ровно одна еда; появляется на случайной свободной клетке.
- **FR-7.** Съедание еды: длина +1, счёт +10, появляется новая еда.

### Смерть и раунды

- **FR-8.** Столкновение со стеной или собственным телом — конец игры.
- **FR-9.** Экран Game Over: счёт, рекорд, кнопка «Заново».
- **FR-10.** Пауза (P / Esc / кнопка): поле затемняется, движение останавливается,
  ввод направлений во время паузы игнорируется.

### Сложность и скорость

- **FR-11.** Скорость растёт с очками: старт 6 клеток/с, ускорение каждые 50 очков,
  максимум 15 клеток/с. Числа — в конфиге, тюнятся отдельно от кода.
- **FR-12.** В меню выбор стартовой сложности (лёгкая / средняя / сложная) —
  отличается стартовой скоростью.

### Счёт и хранение

- **FR-13.** Счёт и текущая длина видны во время игры (HUD).
- **FR-14.** Рекорд хранится в localStorage отдельно по каждой сложности,
  показывается в меню и на Game Over.

### Экраны

- **FR-15.** Поток экранов: Меню → Игра → (Пауза) → Game Over → Меню/Заново.

## 5. Нефункциональные требования

- **NFR-1.** Производительность: стабильные 60 FPS при длине змейки до 400 клеток.
- **NFR-2.** Отклик на управление: смена направления применяется не позднее
  следующего игрового тика.
- **NFR-3.** Игровая логика детерминирована и не зависит от DOM — покрывается
  юнит-тестами без браузера.
- **NFR-4.** Размер бандла < 100 КБ (без шрифтов), первичная загрузка < 1 с
  на среднем железе.
- **NFR-5.** Адаптивность: canvas масштабируется под окно с сохранением пропорций
  поля; на узких экранах — управление свайпами.
- **NFR-6.** Доступность: игра полностью проходима с клавиатуры; контраст
  текста HUD ≥ 4.5:1.

## 6. Критерии приёмки v1 (Definition of Done)

- [ ] Каждое FR реализовано и закрыто тестом логики либо пройдено по ручному чек-листу.
- [ ] `npm run build` проходит без ошибок и без предупреждений типов.
- [ ] Юнит-тесты зелёные, покрытие `src/core/` ≥ 90% строк.
- [ ] Смоук-чек пройден: раунд в Chrome (desktop) и в мобильном режиме DevTools.
- [ ] Рекорд переживает перезагрузку страницы.

## 7. Риски и открытые вопросы

- Тюнинг скоростей FR-11 требует игротестов — числа в конфиге подобраны «на глаз».
- Нужен ли счёт за одновременное поедание на грани тика (edge case FR-7) — уточнить на реализации.
- Звук отложен в v2, но события ядра (`ate`, `died`) уже должны существовать, чтобы подписаться позже.
