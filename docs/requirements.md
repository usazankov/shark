# Требования к игре «Змейка»

- Версия: 1.1 (стек сменён на C + Raylib по решению заказчика)
- Дата: 2026-10-03
- Статус: v1 — классическая змейка, без мультиплеера

## 1. Обзор

Классическая «Змейка»: игрок управляет змейкой на клеточном поле, собирает еду,
растёт и не должен врезаться в стены и в собственное тело. Цель — набрать
максимум очков. Одна партия длится 1–5 минут.

## 2. Цели и не-цели

**Цели v1:**

- Играбельная классическая змейка — нативное desktop-приложение на C.
- Хардкор-подход: минимум зависимостей, максимум контроля, ноль магии фреймворков.
- Чистая, тестируемая архитектура: игровая логика на чистом C без графической
  библиотеки, покрытая юнит-тестами.
- Рекорды сохраняются между запусками.

**Не-цели v1** (архитектура должна допускать добавление позже):

- Мультиплеер, онлайн-таблица рекордов.
- Уровни, препятствия, бонусы кроме базовой еды.
- Звук и музыка.
- Порты на другие платформы (raylib кроссплатформенный, но v1 делаем и
  принимаем только на Windows).

## 3. Стек и платформа

| Что        | Решение                          | Почему                                                        |
| ---------- | -------------------------------- | ------------------------------------------------------------- |
| Язык       | C (C11, без расширений компилятора) | Максимальный контроль и предсказуемость; меньше мест, где спрятаться багу |
| Графика    | Raylib                           | Библиотека C99 из ~100 функций; в официальных примерах есть змейка; ноль магии |
| Сборка     | CMake + Ninja                    | Стандарт индустрии; пресеты под MinGW/MSVC/Linux              |
| Тесты      | Unity (ThrowTheSwitch) + CTest   | Минималистичный фреймворк на чистом C; тесты логики без окна  |
| Компилятор | GCC, MinGW-w64 UCRT64 (MSYS2)  | Свободный, документированный, raylib ставится через pacman (только UCRT64) |
| Движок     | нет — raylib это библиотека, не движок | Змейке не нужен менеджер сцен/сущностей; свой цикл = свой контроль |

Поддерживаемая платформа v1: Windows 10/11 x64. Кроссплатформенность — бонус
на будущее (код ядра и raylib платформенно-нейтральны, платформозависимы только
пути файла рекордов и точка входа).

## 4. Функциональные требования

У каждого требования есть ID — на него ссылаются коммиты, тесты и ревью.

### Игровое поле

- **FR-1.** Поле — сетка клеток N×M. Базовый размер 20×20, задаётся в конфиге.
- **FR-2.** Змейка стартует длиной 3 в центре поля, начальное направление — вправо.

### Управление

- **FR-3.** Управление: стрелки и WASD. Окно игры ловит ввод и без мыши.
- **FR-4.** Разворот на 180° игнорируется — нельзя умереть от нажатия «назад».
- **FR-5.** Ввод буферизуется (очередь до 2 направлений), чтобы быстрые
  последовательные повороты не терялись.

### Еда и рост

- **FR-6.** На поле всегда ровно одна еда; появляется на случайной свободной клетке.
- **FR-7.** Съедание еды: длина +1, счёт +10, появляется новая еда.

### Смерть и раунды

- **FR-8.** Столкновение со стеной или собственным телом — конец игры.
- **FR-9.** Экран Game Over: счёт, рекорд, «Заново» (клавиша R или Enter).
- **FR-10.** Пауза (P / Esc): поле затемняется, движение останавливается,
  ввод направлений во время паузы игнорируется.

### Сложность и скорость

- **FR-11.** Скорость растёт с очками: старт 6 клеток/с, ускорение каждые 50 очков,
  максимум 15 клеток/с. Числа — в конфиге, тюнятся отдельно от кода.
- **FR-12.** Выбор стартовой сложности при запуске (1/2/3 или клавиши) —
  отличается стартовой скоростью.

### Счёт и хранение

- **FR-13.** Счёт и текущая длина видны во время игры (HUD).
- **FR-14.** Рекорд хранится в файле рядом с бинарником (или `%APPDATA%/snake/`),
  отдельно по каждой сложности, показывается на Game Over и при старте.

### Экраны

- **FR-15.** Поток экранов: Меню → Игра → (Пауза) → Game Over → Меню/Заново.
  Экраны — состояния ядра, отрисовываются тем же рендером.

## 5. Нефункциональные требования

- **NFR-1.** Производительность: стабильные 60 FPS при длине змейки до 400 клеток
  (запас по рендеру — raylib рисует это без усилий, узким местом должна не стать
  и логика).
- **NFR-2.** Отклик на управление: смена направления применяется не позднее
  следующего игрового тика.
- **NFR-3.** Игровая логика детерминирована, не зависит от raylib/окон/файлов и
  покрывается юнит-тестами без запуска графики.
- **NFR-4.** Размер бинарника < 2 МБ (raylib статически ~1 МБ); холодный запуск
  < 1 с.
- **NFR-5.** Окно: фиксированный расчётный размер под поле; опционально —
  ресайз с вписыванием поля с сохранением пропорций клеток (IsWindowResized).
- **NFR-6.** Игра полностью проходима с клавиатуры; контраст текста HUD ≥ 4.5:1.
- **NFR-7.** Компиляция с `-Wall -Wextra -Wpedantic -Werror -std=c11` — ноль
  предупреждений. Это часть определения «собралось».

## 6. Критерии приёмки v1 (Definition of Done)

- [ ] Каждое FR реализовано и закрыто тестом логики либо пройдено по ручному чек-листу.
- [ ] `cmake --build build --config Release` проходит с нулём предупреждений (NFR-7).
- [ ] `ctest --test-dir build` зелёный; покрытие логики `src/core/` ≥ 90% строк
      (проверка покрытия — по возможности, gcovr/llvm-cov).
- [ ] Смоук-чек пройден: раунд на Windows 10 x64 из чистой сборки.
- [ ] Рекорд переживает перезапуск игры (FR-14).

## 7. Риски и открытые вопросы

- Тюнинг скоростей FR-11 требует игротестов — числа в конфиге подобраны «на глаз».
- Формат файла рекордов: v1 — простой текст; если понадобятся настройки —
  пересмотреть на мини-INI/JSON.
- Утечки памяти: C без RAII — ядро владеет состоянием через arena/очистку;
  проверять Valgrind/ASan хотя бы раз перед релизом v1.
