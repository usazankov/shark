# Проверка «Змейки»

Шаги 1–2 — обязательный минимум после любого изменения кода. Дальше — по контексту.

## 1. Сборка и тесты

```bash
npm run build   # сборка без ошибок TS
npm test        # юнит-тесты core-логики
npm run lint    # если скрипт есть в package.json
```

Падение любого шага = проверка не пройдена, дальше не двигаться.

## 2. Смоук в браузере

Нужно, когда правились `render/`, `input/`, экраны или `main.ts`.
Подними dev-сервер (`npm run dev`), открой игру в браузере и прогони один раунд.

Чек-лист смоука:

- [ ] Из меню игра начинается, змейка движется вправо
- [ ] Повороты работают; разворот на 180° игнорируется (FR-4)
- [ ] Еда съедается, длина и счёт растут (FR-7)
- [ ] Столкновение со стеной и с собой → Game Over; «Заново» работает (FR-8, FR-9)
- [ ] Пауза останавливает движение и затемняет поле (FR-10)
- [ ] Рекорд сохраняется после перезагрузки страницы (FR-14)
- [ ] FPS не проседает, поле вписывается в окно без искажений (NFR-1, NFR-5)

## 3. Отчёт

Отчитывайся честно и конкретно: какие шаги запущены, что зелёное, что сломано —
с текстом ошибки и командой, которая её дала. «Должно работать» — не результат;
результат — «проверил, работает» или «падает вот здесь».
